✓ What holds

  • Skipping frames does not hurt retrieval. On both lectures, at 67–74% fewer calls, hit@5 was higher than full compute. Replicated.
  • It is fast. One hour of video indexed in 5–13 minutes on a laptop GPU — ~3× faster than encoding every frame. The change signal costs 1–2 ms/frame.

✗ What we could not prove

  • Our change-aware router is not measurably better than uniform sampling. It won one lecture by +25% and lost the other by −13%, at identical call counts. On this evidence, the simple baseline you would write yourself is just as good.
  • Two earlier quality claims were withdrawn. “Median 100% answer parity” came from a lenient yes/no check that counted two different slides as a match. A CLIP timestamp metric was discarded for penalising the right slide a few seconds off.
  • Sample size is two lectures, 20 queries each. A real signal — not a published benchmark.

We publish the failures because the saving is the product, and a number that collapses under a customer's scrutiny is worth less than nothing.

Free and open

The router is open source. Take it.

The selection logic is the part you could write yourself — so we are not charging for it. It installs with nothing heavier than numpy and OpenCV, because the whole point is that deciding costs less than the call it avoids.

# the router — no torch, no detector, no encoder in the hot path
pip install frameroute

# what would this cost you? no model, no API key needed
frameroute cost your_video.mp4 --usd-per-call 0.005

# route it, then spend your model only on what came back
python -c "
from frameroute import FrameRouter, analyze_video
track = analyze_video('your_video.mp4')
sel   = FrameRouter().select(track, budget_per_hour=240)
for pick in sel.picks:
    embedding = your_expensive_model(frame_at(pick.idx))
"

Status — read before you deploy

What is ready, and what is not

✓ Production quality

  • The frameroute router, CLI and Python API — 27 tests green, pip-installable, MIT.
  • The measurement harness (grounded_eval, latency, cost_parity) — this is what the audit runs on.

✗ Not production ready

  • The bundled HTTP server has had 7 security defects identified and closed (arbitrary file read, upload path traversal, hardcoded key, wildcard CORS, rate limiter, sports paths, retired chat model). It has not been load-tested or audited for multi-tenant production deployment. Audits run offline; the hosted API is not launched.
  • Evidence is two lectures. Continuous-motion footage (traffic, busy streets, fast sport) is untested for saving and is the case where routing helps least.
